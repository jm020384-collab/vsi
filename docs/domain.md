# Перенесення платформи на власний домен

Домен: **vsi-therapy.com** (реєстратор — GoDaddy, хостинг — Vercel, проєкт `vsi`).

## Що важливо знати про код

У коді **не зашито жодної адреси**. Усе походить від однієї змінної
`NEXT_PUBLIC_SITE_URL`:

| Де використовується                              | Файл                             |
| ------------------------------------------------ | -------------------------------- |
| `metadataBase` — канонічні посилання й OG-теги   | `app/layout.tsx`                 |
| `robots.txt`                                     | `app/robots.ts`                  |
| `sitemap.xml`                                    | `app/sitemap.ts`                 |
| Посилання в листі підтвердження пошти            | `lib/actions/verify-email.ts`    |
| Посилання в листі скидання пароля                | `lib/actions/reset-password.ts`  |
| Посилання для фахівця у сповіщенні про звернення | `lib/actions/contact-request.ts` |

Тобто переїзд — це налаштування, а не правки коду. Але якщо забути оновити
змінну, сайт відкриватиметься за новим доменом, а **листи вестимуть людей на
стару адресу** — і підтвердження пошти перестане працювати.

## Порядок дій

Послідовність важлива: змінні оточення міняємо **після** того, як домен
реально запрацював, інакше посилання в листах поведуть у нікуди.

### 1. Додати домен у Vercel

Settings → Domains → Add Existing. Додати `vsi-therapy.com` і
`www.vsi-therapy.com`; головним зробити короткий, `www` залишити на редірект.

SSL Vercel випускає сам. У GoDaddy сертифікат купувати не треба.

### 2. DNS у GoDaddy

Значення брати **з екрана Vercel**: CNAME для піддомену унікальний для
кожного проєкту (вигляду `d1d4fc829fe7bc7c.vercel-dns-017.com`), загальні
значення з інтернету дадуть «invalid configuration».

У GoDaddy → DNS замінити два наявні записи, що ведуть на паркувальну
сторінку:

- `A` для `@` → значення з Vercel
- `CNAME` для `www` → значення з Vercel

Нейм-сервери на Vercel **не переводити**: тоді довелося б вручну переносити
решту записів, зокрема поштові.

### 3. Змінні оточення у Vercel

Коли домен відкривається:

```
NEXT_PUBLIC_SITE_URL = https://vsi-therapy.com
AUTH_URL             = https://vsi-therapy.com
```

`AUTH_URL` в Auth.js v5 потрібен лише за нестандартного base path, і на
Vercel його можна взагалі прибрати — хост береться із заголовків запиту.
Але поки змінна задана, вона мусить вказувати на чинний домен, інакше вхід
поведе на стару адресу.

Після зміни — **Redeploy**. Змінні з префіксом `NEXT_PUBLIC_` вшиваються у
збірку, старий деплой нового значення не побачить.

### 4. Пошта

Поточний відправник використовує `onboarding@resend.dev` — тестову адресу
Resend. Листи з неї доходять **лише на власну адресу власника акаунта
Resend**; реєстрація й скидання пароля для решти користувачів не працюють.

Resend → Domains → Add Domain → `vsi-therapy.com`. Додати видані TXT і MX
(DKIM, SPF) у GoDaddy — вони не конфліктують із записами Vercel. Далі:

```
EMAIL_FROM = VSI <noreply@vsi-therapy.com>
```

### 5. Перевірка

```
nslookup vsi-therapy.com
curl -sI https://vsi-therapy.com | head -5
```

- `https://vsi-therapy.com/robots.txt` і `/sitemap.xml` містять новий домен
- зареєструвати тестовий акаунт фахівця: лист приходить, посилання в ньому
  веде на `vsi-therapy.com`
- увійти й вийти: сесія тримається

## Чого робити не треба

- **OAuth-редіректи.** Вхід лише через email і пароль (`auth.ts`,
  провайдер `Credentials`). Google як провайдер не підключений, попри
  наявність ключів у змінних.
- **Cloudflare Turnstile.** Ключі в змінних є, у коді капча не
  використовується.
- **`NEXT_PUBLIC_APP_URL`.** Мертва змінна, у коді не читається ніде.
  Залишилася у продакшн-змінних Vercel, можна видалити:

```
vercel env rm NEXT_PUBLIC_APP_URL production
```

## Після переїзду

`vsi-sable.vercel.app` продовжить працювати. Коли `NEXT_PUBLIC_SITE_URL`
вказує на новий домен, канонічні посилання ведуть туди, і пошукові системи
переповзають самі.
